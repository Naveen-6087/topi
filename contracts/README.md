# Shielded pool contracts

A Foundry library for a post-quantum shielded pool on EIP-8141 (frame transactions). Spends are
proven with Spartan-WHIR client proofs, aggregated by leanVM recursion into one terminal proof, and
verified on chain by a WHIR terminal verifier generated with
[ethereum/sol-whir-p3](https://github.com/ethereum/sol-whir-p3). Validation runs in Yul accounts that
EIP-8141 VERIFY frames call: the pool's own account, and a paymaster whose operator authorizes with a
leanSPHINCS (hash-based) signature.

The contracts are deployed on chain 8141 (see [Deployments](#deployments)). The deployed bytecode is
the contract of record: interface, storage layout and Yul output must not change.

## Layout

```
contracts/
├── src/
│   ├── ShieldedPool.sol            pool logic (GENERATED from codegen/ShieldedPool.tmpl.sol)
│   ├── StatementBinding.sol        binds the terminal proof's application root to the spends
│   ├── hash/KoalaPoseidon2x24.sol  Poseidon2 (KoalaBear, width 24) + hash_fields (GENERATED)
│   ├── interfaces/                 IShieldedPool, ITerminalVerifier, ILeanSphincsVerifier
│   └── verifier/                   generated leanVM grouped terminal verifier (sol-whir-p3)
├── yul/
│   ├── PoolAccount.yul             the pool's EIP-8141 account
│   ├── PQPaymaster.yul             leanSPHINCS paymaster
│   ├── ClassicPaymaster.yul        ECDSA paymaster (first deployment)
│   └── build/*.bin                 deployed initcode (checked by script/build-yul.sh --check)
├── codegen/                        generators and their inputs (see Codegen)
├── script/build-yul.sh             compiles the Yul accounts with the pinned solc
├── test/                           Foundry tests; fixtures/ holds the real terminal proof
└── lib/                            forge-std, sol-whir-p3 (git submodules, pinned)
```

## Build and test

```sh
git submodule update --init --recursive
forge build
forge test                      # all tests, including settlement of the real terminal proof
script/build-yul.sh --check     # the Yul sources still compile to yul/build/*.bin
```

`foundry.toml` pins solc 0.8.28 with via-IR and a short Yul optimizer step sequence (the default
sequence takes more than 30 minutes on the unrolled Poseidon2 permutation).

The Yul accounts are compiled with

```sh
solc 0.8.28 --strict-assembly --evm-version prague --optimize --bin yul/<Name>.yul
```

`script/build-yul.sh` runs exactly that (it finds solc 0.8.28 through `$SOLC`, `PATH`, or the svm cache
that `forge build` fills) and writes `yul/build/<Name>.bin`. With `--check` it fails if any output
differs from the committed bins, which are the initcode of the deployed accounts.

The tests read `../lean/PoolModel/Frames.lean` (the Lean model of the frame policy) for the parity
test, so run them from a checkout of the whole repository.

## Using it as a dependency

```sh
forge install <org>/<repo>
```

Add remappings (adjust the path to where the library lands under `lib/`):

```
shielded-pool/=lib/<repo>/contracts/src/
sol-whir-p3/=lib/<repo>/contracts/lib/sol-whir-p3/src/
```

Then, for example:

```solidity
import { IShieldedPool } from "shielded-pool/interfaces/IShieldedPool.sol";
import { StatementBinding } from "shielded-pool/StatementBinding.sol";
```

## Contracts

**ShieldedPool** (`src/ShieldedPool.sol`). The pool logic. It never runs at its own address: the pool
account DELEGATECALLs it, so all state lives in the pool account. A deposit takes ether and a
precommitment, assigns a label, builds the note `hash_fields(NOTE, pool || label || amount ||
precommitment)` and appends it to a depth-32 pool tree, and the label to an association tree. `settle`
takes the calldata of one terminal proof and the 82 public transaction fields of two spends. It calls
the terminal verifier, recomputes the application root the proof commits to from the two spends
(`StatementBinding`), checks the pool, scope, roots and nullifiers, pays the recipient and the fee
recipient, and appends the two change commitments. Only the pool itself may call `settle`, i.e. the
SENDER frame of a transaction whose VERIFY policy passed. `Deposited` and `Settled` carry every tree
leaf, so wallets rebuild both trees from logs.

**StatementBinding** (`src/StatementBinding.sol`). Recomputes spartan-whir's statement digest (a
Poseidon1 duplex over a length-prefixed domain and the public inputs; a precomputed variant for the
8-element lean statement) and leanVM's binary application root over two statement digests.

**KoalaPoseidon2x24** (`src/hash/KoalaPoseidon2x24.sol`). Poseidon2 over KoalaBear, width 24, as fully
unrolled Yul, plus spartan-whir's withdrawal `hash_fields` and tree node hashes.

**LeanVmGroupedTerminal_KeccakPow28T6Lean** (`src/verifier/`). The terminal verifier generated by
sol-whir-p3 for the fixed leanVM recursion program (grouped LogUp, Keccak transcript, 28-bit PoW, lean
statement). It implements `ITerminalVerifier.verifyGroupedLogupV1` and returns true for a valid proof.

### Yul accounts

**PoolAccount** (`yul/PoolAccount.yul`). The pool's account code. Calldata of exactly four zero bytes
is the VERIFY entry: it checks the frame layout (the pool is the sender; exactly three frames: the
pool's VERIFY frame, a payer's VERIFY frame, one SENDER frame calling `settle` with zero value) and
approves execution only, so the pool never pays gas. Any other call is DELEGATECALLed to
ShieldedPool, whose address follows the runtime code. The initcode calls `initialize()`. Initcode
arguments: the ShieldedPool address (one word).

**PQPaymaster** (`yul/PQPaymaster.yul`). Pays gas for the pool's transactions that carry exactly one
signature entry: an ARBITRARY (scheme 0) entry with an empty message and 5684 bytes, read with
SIGDATACOPY and checked by the shared leanSPHINCS verifier (`ILeanSphincsVerifier.verify`) against
the operator's key over the transaction's signature hash. EIP-8141 elides that entry from the
signature hash, so the signature covers the whole transaction. Approves payment only. Plain
transfers fund it; the admin withdraws with `withdraw()`. Initcode arguments: pool, admin, verifier,
pkSeed, pkRoot (one word each).

**ClassicPaymaster** (`yul/ClassicPaymaster.yul`). The same policy with one secp256k1 signature by the
operator. Used by the first deployment. Initcode arguments: pool, operator (one word each).

The policies of all three accounts are transcribed, check by check and with the same failure codes,
in the Lean model `lean/PoolModel/Frames.lean`; `test/LeanParity.t.sol` checks that the constants and
failure codes agree.

## Codegen

Two sources are generated; edit the generator or template, never the output.

- `src/ShieldedPool.sol` from `codegen/ShieldedPool.tmpl.sol`, filling in the empty-subtree tables
  `codegen/zeros.txt` (pool tree) and `codegen/zeros-association.txt` (association tree):
  `node codegen/generate.mjs`.
- `src/hash/KoalaPoseidon2x24.sol` from Plonky3's KoalaBear width-24 round constants
  (`codegen/poseidon2/`, Plonky3 rev 458ef54 as pinned by spartan-whir):
  `node codegen/gen_poseidon2_24.mjs`.

Constants that are baked into the sources are printed by `test/Codegen.t.sol`
(`forge test --match-path test/Codegen.t.sol -vv`): the zero tables and the Poseidon1 duplex state
after the constant statement prefix used by `StatementBinding.leanStatementDigest`.

Test vectors: `test/fixtures/vectors.json` is printed by `codegen/vectors.rs`, run as an example inside
a spartan-whir checkout; `test/fixtures/lean/` holds the lean statements and the transaction fields of
the two spends behind the terminal proof in `test/fixtures/terminal/`.
