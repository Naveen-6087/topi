`contracts/` is a Foundry library. The pool's logic is Solidity; everything that runs in an EIP-8141 VERIFY frame is Yul, because Solidity cannot emit the frame opcodes.

```text
contracts/
├── src/
│   ├── ShieldedPool.sol            pool logic (generated from codegen/ShieldedPool.tmpl.sol)
│   ├── StatementBinding.sol        binds the terminal proof's application root to the spends
│   ├── hash/KoalaPoseidon2x24.sol  Poseidon2 (KoalaBear, width 24) and hash_fields (generated)
│   ├── interfaces/                 IShieldedPool, ITerminalVerifier, ILeanSphincsVerifier
│   └── verifier/                   generated leanVM grouped terminal verifier
├── yul/
│   ├── PoolAccount.yul             the pool's EIP-8141 account
│   ├── PQPaymaster.yul             leanSPHINCS paymaster
│   ├── ClassicPaymaster.yul        ECDSA paymaster
│   └── build/*.bin                 deployed initcode
├── codegen/                        generators and their inputs
├── script/build-yul.sh             compiles the Yul accounts with the pinned solc
└── test/                           Foundry tests and the real terminal proof fixture
```

## Solidity

| Contract | Role |
|---|---|
| `ShieldedPool` | Deposits, the pool and association trees, root history, nullifiers and `settle`. It never runs at its own address: the pool account delegates to it, so all state lives in the pool account. |
| `StatementBinding` | Recomputes spartan-whir's statement digest (with a precomputed variant for the 8-element lean statement) and leanVM's binary application root over two statement digests. |
| `KoalaPoseidon2x24` | Poseidon2 over KoalaBear, width 24, as fully unrolled Yul, plus `hash_fields` and the tree node hashes. About 68,600 gas per permutation. |
| `LeanVmGroupedTerminal_KeccakPow28T6Lean` | The terminal verifier generated by `ethereum/sol-whir-p3` for the fixed recursion programs. Implements `ITerminalVerifier`. |

## Yul accounts

| Account | VERIFY entry | Approves | Initcode arguments |
|---|---|---|---|
| `PoolAccount` | calldata `0x00000000` | Execution only, for the exact settle shape; other calls are delegated to `ShieldedPool` | `ShieldedPool` address |
| `PQPaymaster` | calldata `0x00000000` | Payment, for the pool's transactions with exactly one leanSPHINCS `ARBITRARY` witness by the operator | pool, admin, verifier, `pkSeed`, `pkRoot` |
| `ClassicPaymaster` | calldata `0x00000000` | Payment, for the pool's transactions with exactly one secp256k1 signature by the operator | pool, operator |

Each argument is one 32-byte word appended to the initcode. `PoolAccount`'s initcode also calls `initialize()` on the logic to record the empty roots. Both paymasters are funded by plain transfers and pay out with `withdraw()` (`0x3ccfd60b`) to their admin or operator.

The three policies are transcribed check by check, with the same failure codes, in the Lean model; a parity test reads `lean/PoolModel/Frames.lean` and checks that constants and failure codes agree. See [Formal verification](/architecture/formal-verification).

## Build and test

```bash
cd contracts
git submodule update --init --recursive
forge build
forge test                      # includes settlement of the real terminal proof fixture
script/build-yul.sh --check     # the Yul sources still compile to yul/build/*.bin
```

| Test suite | Covers |
|---|---|
| `ShieldedPool.t.sol` | Deposits, settlement of the real terminal proof fixture, and every rejection case |
| `StatementBinding.t.sol` | Statement digests and application roots against the Rust vectors |
| `TerminalVerifier.t.sol` | The generated verifier on the real proof fixture, and the calldata layout `ShieldedPool` relies on |
| `Interfaces.t.sol` | The interfaces match the implementation and the selectors the Yul accounts hard-code |
| `LeanParity.t.sol` | Yul constants and failure codes agree with the Lean model |
| `Codegen.t.sol` | Prints the constants baked into the generated sources |

`foundry.toml` pins solc 0.8.28 with via-IR and a short Yul optimizer step sequence. The Yul accounts are compiled with `solc --strict-assembly --evm-version prague --optimize --bin`; `build-yul.sh --check` fails if the output differs from the committed initcode. Tests read the Lean model, so run them from a checkout of the whole repository.

## Generated sources

Edit the generator or template, never the output:

| Output | Generator |
|---|---|
| `src/ShieldedPool.sol` | `node codegen/generate.mjs`, from `codegen/ShieldedPool.tmpl.sol` and the empty-subtree tables |
| `src/hash/KoalaPoseidon2x24.sol` | `node codegen/gen_poseidon2_24.mjs`, from Plonky3's KoalaBear width-24 round constants |
| `src/verifier/*.sol` | `ethereum/sol-whir-p3` fixture generator, for the pinned recursion programs |

<Note>
The deployed bytecode is the contract of record. Interfaces, storage layout and Yul output must not change for existing deployments; a change needs a new deployment.
</Note>
